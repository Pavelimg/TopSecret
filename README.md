# Medication Schedule API

Учебный backend-сервис для создания графиков приёма лекарств и получения ближайших приёмов пользователя. Проект показывает работу с REST API, валидацией данных и реляционной базой.

> Проект предназначен для демонстрации разработки и не является медицинской системой.

## Возможности

- создание расписания с периодичностью в минутах, часах, днях или неделях;
- получение всех рассчитанных приёмов пользователя;
- выборка приёмов на ближайший час;
- перенос ночных приёмов на утро и округление времени до 15 минут;
- интерактивная документация OpenAPI;
- автоматическое создание структуры SQLite при первом запуске;
- параметризованные SQL-запросы;
- проверка основных сценариев через `pytest`.

## Стек

Python 3.12, FastAPI, Pydantic, SQLite, pytest, Docker.

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8080
```

После запуска доступны:

- Swagger UI: `http://127.0.0.1:8080/docs`
- OpenAPI: `http://127.0.0.1:8080/openapi.json`
- health check: `http://127.0.0.1:8080/health`

Путь к базе можно изменить через переменную `DATABASE_PATH`; пример находится в `.env.example`.

## Запуск в Docker

```bash
docker build -t medication-schedule-api .
docker run --rm -p 8080:8080 medication-schedule-api
```

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка доступности сервиса |
| `POST` | `/schedule` | Создание графика приёма |
| `GET` | `/schedules?user_id=42` | Получение сохранённых графиков |
| `GET` | `/all_takings?user_id=42` | Расчёт всех приёмов |
| `GET` | `/next_takings?user_id=42` | Приёмы в ближайший час |

Пример запроса:

```json
{
  "name": "Vitamin D",
  "time_format": "hours",
  "repeats_value": 12,
  "duration": 10,
  "uuid": 42
}
```

Значение `duration: -1` обозначает открытое расписание; для ответа рассчитываются ближайшие 200 приёмов.

## Тесты

```bash
pytest -q
```

Тесты используют временную SQLite-базу и не изменяют рабочие данные.
